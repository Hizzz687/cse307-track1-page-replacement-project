## Project summary

This project compares FIFO, LRU, Belady's Optimal, and a lightweight learned eviction
policy. The learned policy is a small decision tree trained on candidate-page features:
recency, access frequency, and page identifier. Training labels are generated by asking
Belady's Optimal which page would be the best victim on a separate trace.

The experiment deliberately shifts from locality-heavy/sequential access to random/bursty
access halfway through the trace. Results are reported separately for both phases.

## Setup and run

The simulator is written for Python 3.10+; Pillow and ReportLab are used for the
generated chart and PDF report.

```powershell
python -m pip install -r requirements.txt
```

```powershell
python run_experiment.py
```

This creates:

- `results/metrics.csv` - hit/fault metrics before and after the shift.
- `results/hit_ratio.svg` - chart comparing hit ratios.
- `results/hit_ratio.png` - chart embedded in the PDF report.
- `results/trace_summary.txt` - fixed seed and workload parameters.

To create the PDF report after generating results:

```powershell
python make_report.py
```

The PDF is written to `report/Mim_Mahizur_Rahman_CSE307_Track1_Report.pdf`.

## Reproducibility

The workload uses seed `307`, 2,400 requests, 32 virtual pages, and a cache capacity
of 8 frames. The shift occurs at request 1,200. The learned policy is trained from
the same workload generator with a separate training run in the implementation; the
test workload is never used to create the learned model's labels.
